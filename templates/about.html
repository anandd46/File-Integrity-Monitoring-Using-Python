How it works

  1. Register a directory you are authorised to monitor.
  2. Baseline: every file is hashed with SHA-256 and the result is stored as the trusted reference.
  3. Scan: files are hashed again and compared with the baseline: UNCHANGED, MODIFIED, NEW, DELETED, or ERROR when a file could not be read.
  4. Review events and reports. Rebaseline only deliberately, after confirming a change is legitimate.

Web application security controls

  • Server-side validation of every path, ID, filter, page number and interval
  • Path traversal and symbolic-link containment checks
  • Parameterised SQL with allow-listed sort fields
  • Jinja2 autoescaping, no innerHTML, strict Content Security Policy
  • CSRF tokens on every state-changing POST
  • Security headers, safe error pages, localhost-only binding
  • CSV formula-injection protection

A detected change is an indicator of possible tampering or of an ordinary edit. It is not proof of malicious activity.
